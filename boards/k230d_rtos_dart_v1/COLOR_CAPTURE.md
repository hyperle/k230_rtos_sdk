# SC132GS 彩色取帧与呈现

## 使用

运行 `/sdcard/examples/dart/camera_color_preview.py`。脚本使用当前固件已经支持的
`Sensor.RGB565`，通过 `Display.VIRT(..., to_ide=True)` 向 CanMV IDE 输出
640×480 彩色预览。输入仍是逻辑 CSI0 四线的 1080×1280 模式；未改动外部
24 MHz 时钟和 MIPI 寄存器。

当前示例默认持续预览，不自动保存照片。下方照片与第 60 帧的说明仅记录早期测试。
默认手动曝光 5000 µs、模拟增益 4 倍，亮度可用 `EXPOSURE_US` / `ANALOG_GAIN` 调整。
IDE 停止按钮或 Ctrl-C 结束脚本。此次增加的是 Python 示例，启用彩色无需重新烧录。

## 已有实板证据

用户确认调焦后灰度画面正常。随后改用 RGB565，已真实收到并保存彩色 JPEG，
能分辨蓝色衣服、木色桌面和书脊颜色。主机文件为
`output/k230d_canmv_dart_v1_defconfig/sc132gs-color-review/sc132gs_color_auto.jpg`，
尺寸 640×480，文件 89554 字节；不是灰度上色、ISP 测试图或主机合成图。

首轮彩色脚本启用了自动曝光，终端记录至少 500 帧并保存 JPEG；同次 UART0
记录了连续的原生曝光设置错误，因此不能将此记录当作自动曝光验证通过。
当前正式示例关闭自动曝光，保留 ISP 的彩色处理和白平衡。

手动曝光版已在再次断电上电后直接运行，终端记录至少 2000 帧且脚本仍在运行，
MCP 预览实际返回新帧，`sc132gs_color_preview.jpg` 为该轮预览存档；
`sc132gs_color.jpg` 为该轮第 60 帧保存的 RGB JPEG，59274 字节。
12 秒 UART0 采样仍有不支持 OTP 读取的提示，未见该轮连续曝光设置失败；
采样开头含一条此前残留并带乱码的曝光错误，不据此宣称串口完全没有错误。
这段带主动 sleep 的循环只验证彩色到帧和显示，不用于声称达到传感器标称帧率。

## 尚未解决的限制

停止/软重启后仍复现过 VICAP NOTREADY，首个原生错误为传感器软件复位寄存器
`0x0103` 写入失败，需整板断电后才能恢复的现象仍在排查。这不应被表述为固件
所有初始化路径已正常。真实彩色取帧成立，但色彩准确度、Bayer 顺序和当前镜头
对应的 ISP 标定仍未用标准色卡验证。
