## 本次补丁

继续采用“同步失败，不发布图像”的方法，仅修改两个运行时 C 文件：

1. `port/omv/ide_dbg_vo_wbc.c`：此前忽略 JPEG 输出 DMA 搬运结果和缓存失效
   返回值，可能把旧字节或部分新字节作为成功预览提交。现在遇到失败先归还本次
   编码码流，返回失败；公共接口清空输出指针、大小、尺寸。错误发生在编码完成后，
   不改变先前输入帧生命周期。下一次成功编码仍能继续。
2. `port/modules/modmedia.display.c`：复制与直接显示两条路径的 cache flush
   失败时均停止提交。原来缓冲区不足时只复制前缀、仍发布完整图像描述；现在拒绝
   该帧，避免硬件读取不完整图像。诊断信息明确区分容量、显示同步和 IDE DMA/缓存。

相机驱动、寄存器表、四线 CSI0、外部 24 MHz、I2C 时序、ISP 数据库和曝光/增益
参数均沿用 I2C_ABORT_FIXED。本次不是重新调节这些参数。
原有 I2C abort 位号修复和失败停流保护也保留。
随镜像预览脚本仍默认持续运行、不自动保存照片；使用说明已同步改为当前行为。

## 验证与边界

主机对真实生产函数实施故障注入：WBC 原来的 5 项测试保留，并将 JPEG 输出改为
分离的 CPU 缓存与设备内存模型，新增 DMA 失败、部分 DMA、invalidate 失败、
下一帧恢复 4 项。修改前这 4 项均失败，修改后全部通过。
Display 测试编译两个实际提交函数及真实缓冲区结构体，使用 SDK 帧类型；
7 个场景覆盖正常复制/直接提交、两类 flush 失败、容量不足、无效状态和重试。
其中 4 个场景在修改前失败。

本轮共 21 个 CTest 回归目标全部通过：9 项 VICAP、9 项 WBC，以及 Sensor、
Display、devfs 三个目标；Sensor 内含 3 项 Python 测试，Display 内含 7 个 C 场景。
这类失败注入证明错误处理缺陷存在，不证明真实紫条期间发生了同一错误。

完整离线构建退出码 0，日志证实两个运行时 C 文件重新编译。32 项输入构建前后
哈希一致。校验从交付镜像读取实际解释器，与新链接及暂存文件一致，并检查了新旧
缓冲区诊断代码、持续预览脚本、ISP 数据库、MBR/FAT 分区及 A/B 内核封装。
实际内核槽解包后与本次 raw kernel/ELF 一致；八个相机/I2C/devfs 函数字节与
I2C_ABORT_FIXED 一致。
