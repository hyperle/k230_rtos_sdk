## 修改范围

基线为 BUFFER_GUARD，只修改五个运行时输入：`sc132gs.c`、`sensor_comm.c`、
`sensor_dev.h`、冻结的 `media/sensor.py`、MicroPython `core/main.c`。
驱动结构体布局与 ioctl ABI 未改变；头文件只增加一个验证函数声明。

1. **真实控制状态校验。** SC132GS 的上电缓存需要同时满足 EN/reset 引脚的
   FPIOA GPIO 复用、输出 DDR、实际读回电平。公共 S_POWER 缓存和同模式 S_INIT
   缓存也调用这项验证，不能再跳过驱动。其他传感器的健康缓存路径保持原行为。
   S_INIT 缓存另要求 power/init/mode 三项状态一致。
2. **失败回滚。** 初始化失败时清除模式状态，尝试通过实际控制脚确认关电。
   不再额外发送 `0x0100=0` I2C 清理写，避免覆盖首次失败事务的控制器现场。
   保留原始初始化返回值，另记关电清理结果。GPIO 失败或读回不符时保留不确定的
   上电状态；公共分发不能强行把失败关电记成已关电。
3. **Sensor 生命周期。** 单 Sensor 的 init、取 fd 或启动流失败时执行有序回滚。
   回滚失败只补充日志，原始错误继续抛出；下一次 `run()` 在重新下发配置前先完成
   未完成的清理。停止失败不继续 deinit；deinit 失败不释放 CSI 槽位，成功步骤不重复。
   fd 获取失败也返回真实错误码，清理成功后 fd 失效。
4. **重复对象。** `force=True` 重用 CSI 前必须先成功清理原对象；失败不得抢占。
   已退休对象的迟到析构或 stop 不再操作新对象的槽位。构造中途失败而未占槽位的
   对象，其析构不再调用相机接口。
5. **IDE 软重启确认。** 工作线程退出后、GC/媒体池/VM 释放前，在仍有效的 VM
   中调用已加载的 `Sensor.deinit()`。类清理发现仍有原对象占有设备即报告失败。
   失败时保留 VM 和资源，恢复 REPL/IDE 服务并打印
   `[camera] cleanup incomplete; soft reset deferred, resources retained`；不继续释放
   后再创建新 VM。可通过原对象的 `stop()` / `Sensor.deinit()` 重试。

本版保留 BUFFER_GUARD 的 VICAP/WBC 缓存与所有权修复、显示/DMA 输出检查、devfs
防护、I2C abort 位号修正、失败停流 EN 保护。相机寄存器表、四线逻辑 CSI0、
外部 24 MHz、GPIO2、I2C1 GPIO34/35、地址 0x30、默认时序和 ISP 数据库均沿用。
没有加入额外 I2C 健康读取门槛、自动重启、无限重试、总线恢复或延长关电矩阵。
彩色示例保持持续预览、不自动保存照片。

与已撤回 RECOVERY_FIXED 的区别是：复用了有证据的引脚缓存校验方法，但不使用
其启动前 I2C 健康读；本次另补初始化失败关电回滚、force/析构所有权和 VM 释放前
确认。旧版本的取帧次数不计入本候选验收。

## 本轮板卡状态与尚未验证的事项

最初 IDE 查询为无脚本运行。随后下载板端解释器时工具报告未发现板卡，因此本轮
没有取得可用的新解释器哈希，不能假定用户当前安装的是哪一个候选。
用户接回 UART0 后，主机确认 CH340 枚举，但 CanMV USB 已不可见。被动 UART 窗口
没有收到字节；随后请求 shell 提示符也无响应，工具明确未执行诊断命令。
没有运行相机脚本、写寄存器、复位、刷机或存图，不将旧终端计数当作本轮结果。

当前五项修改解决的是可证明的软件状态缺陷；并不证明历次真实地址 NACK 都由
这些缺陷导致。确认下一版可用仍需要烧录本镜像、核对解释器与新内核指纹，再做：
冷启动首帧、至少 600 秒真实连续帧、正常停止立即重跑、IDE 停止立即重跑，以及
失败启动/force 重用时保留第一条 UART 原生错误。紫色条带需要单独观测。

闭源 MPI/ISP 内部仍可能在错误路径中自行释放资源，本版不能证明其全部异步回调
已安全退出。软重启确认覆盖加载的 `media.sensor` 实例；绕过 Sensor 直接使用
原始 MPI 的资源仍沿用原生全局清理。多相机启动辅助方法没有重构自动回滚。
软重启保护失败返回 REPL 前，显示、工作线程和部分外围服务已经停止；该分支
保留 VM 以允许清理重试，不承诺所有外围服务自动恢复。
